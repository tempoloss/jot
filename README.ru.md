# jot

Telegram-бот, который сохраняет заметки и задачи как GitHub Issues. Без
зависимостей, работает на Cloudflare Workers.

[English version](README.md)

```
купить зарядку         заметка
фото + подпись         заметка с картинкой, /pic 5 вернёт её
/rmpic 5               убрать картинку из заметки 5
/task 5                повысить заметку 5 до задачи
/t текст               сразу задача
/list                  открытые задачи, с возрастом
/notes                 последние заметки
/done 3                закрыть
/c 3 текст             комментарий
/rm 5                  удалить заметку 5, спросит; /rm 5! подтверждает
```

И в обратную сторону: он приносит уведомления с GitHub. Кто-то ответил в issue
или пулл-реквесте, где ты участвуешь, — ответ придёт в Telegram в пределах
минуты, со ссылкой на сам комментарий:

```
JAicewizard ответил в duckdb/community-extensions#2431
faiss: exclude windows_amd64 and windows_amd64_mingw

  `_rtools` is the old name for `_mingw`, this looks good to me
```

## Все, кто не ты

Бот на одного человека. По умолчанию он не отвечает незнакомцу вообще ничего и
даже не подтверждает, что существует.

Задай `STRANGER_PHOTO` — Telegram `file_id` — и `/start` от любого другого
вернёт эту картинку, один раз на аккаунт в сутки, а тебе придёт, кто постучался.
Это обмен молчания на характер, и он делается осознанно, а не по умолчанию.

```bash
wrangler secret put STRANGER_PHOTO     # по желанию, Telegram file_id
```

Повторный `/start` с того же аккаунта не стоит ни одного вызова API. Поводом
стали девять сообщений за минуту, которые раньше обходились в восемнадцать
вызовов. Уведомления вдобавок ограничены по часу, потому что дедуп по человеку
ничего не даёт против толпы. Если картинку доставить не удалось, например
незнакомец закрыт для бота, тебе всё равно сообщат, что он приходил: потерять
единственное внешнее событие, которое этот бот вообще видит, из-за упавшего
украшения — не тот порядок.

## Лови без разбора, сортируй потом

Любое обычное сообщение — **заметка**. В момент отправки решать нечего: ни
«задача или заметка», ни категория. Захват безусловный, потому что решение на
захвате — это трение, а трение на захвате убивает личный таскменеджер.

Сортировка отдельно: `/task N` повышает заметку, когда ты уже решил, что это
дело. Заметка — запись, её не закрывают; задачу можно.
См. [ADR 0001](docs/adr/0001-plain-text-is-a-note.md).

## Почему так

| решение | почему | детали |
|---|---|---|
| По умолчанию заметка, не задача | ноль решений на захвате | [ADR 0001](docs/adr/0001-plain-text-is-a-note.md) |
| GitHub Issues как хранилище | уже база задач с API и мобильным приложением | [ADR 0002](docs/adr/0002-github-issues-as-the-store.md) |
| Cloudflare Workers, не рабочий комп | всегда онлайн, не перезагружается, бесплатно | [ADR 0003](docs/adr/0003-cloudflare-workers-not-a-desktop.md) |
| Фото через Telegram `file_id` | без лишних прав, без утечки токена | [ADR 0004](docs/adr/0004-photos-by-file-id.md) |
| Флаг прочитанного у GitHub как хранилище дедупа | нет второй копии правды, дедуп точный | [ADR 0005](docs/adr/0005-github-is-the-dedup-store.md) |
| Удаление спрашивает перед тем, как удалить | второй копии нет, значит отката нет, а `/rm` в трёх символах от `/rmpic` | [ADR 0006](docs/adr/0006-deleting-asks-because-there-is-no-undo.md) |

## Установка

**1. Два приватных репозитория.** Один — этот код, другой, отдельный, —
хранилище задач. Укажешь публичный — все личные заметки станут публичными.

**2. Fine-grained PAT** с **Issues: Read and write**, только на репозиторий
хранилища. Repository access и Permissions — две разные секции, а кнопку Update
token внизу легко пропустить. Для `/rm` нужен ещё admin или maintain: удаление
issue есть только в GraphQL. Без этого права падает ровно одна команда, с
внятной причиной, остальное работает. См.
[ADR 0006](docs/adr/0006-deleting-asks-because-there-is-no-undo.md).

**3. Chat id в Telegram.** Сначала напиши боту — `getUpdates` пустой, пока не
напишешь — потом возьми `result[0].message.chat.id` из
`https://api.telegram.org/bot<TOKEN>/getUpdates`.

**4. Деплой:**

```bash
npm i -g wrangler
wrangler login
wrangler secret put TELEGRAM_TOKEN
wrangler secret put GH_PAT
wrangler secret put WEBHOOK_SECRET     # любая случайная строка
wrangler secret put OWNER_CHAT_ID
wrangler secret put TASK_REPO          # owner/tasks
wrangler deploy
```

**5. Зарегистрируй вебхук** с тем же секретом:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://<твой-хост>" \
  -d "secret_token=<WEBHOOK_SECRET>"
```

`secret_token` обязателен. Без него ботом управляет любой, кто узнал URL, а
хостнеймы обнаружимы. Всё, что не прошло проверку, получает `404`, поэтому
сканер не отличит хост от пустого.

В `wrangler.toml` прописан свой домен, а `workers_dev` и `preview_urls`
выключены: хостнейм `workers.dev` выводится из аккаунта и публикует локальную
часть его почты в URL, который видит любой. Используй тот хост, который настроил
там.

**6. Уведомления GitHub, по желанию.** Нужен **классический** токен со скоупом
`notifications` и больше ничем:

```bash
wrangler secret put GH_NOTIFY_TOKEN
wrangler deploy                        # регистрирует cron
```

Fine-grained токены эти эндпоинты не принимают, поэтому `GH_PAT` тут не подходит.
В `wrangler.toml` укажи свой логин в `GH_LOGIN`. Не задашь секрет — расписание
ничего не делает.

Первый запуск будет молчаливым: опрос берёт весь непрочитанный GitHub inbox,
поэтому отсчёт идёт со следующего настоящего события, а не с истории. После
доставки тред помечается прочитанным, то есть бот чистит твой колокольчик на
GitHub. Это цена за то, что хранилище не нужно вообще. См.
[ADR 0005](docs/adr/0005-github-is-the-dedup-store.md).

## Локальный запуск

Скопируй `.dev.vars.example` в `.dev.vars`, заполни, затем:

```bash
npm run check    # проверить конфиг, ничего не запуская
npm run local    # опрос, без деплоя
```

`local.js` — только для тестов. Он умирает при перезагрузке и умирает молча —
ровно то, от чего спасает Worker. Он импортирует тот же `dispatch`, что и
Worker, поэтому они не разъедутся.

## Тесты

```bash
npm test
```

49 тестов, без сети. Всё разделено так, что часть с сетью — тонкая оболочка над
чистой: `fetch` вокруг `parse` для команд и вызов GitHub вокруг `format` для
уведомлений. Ключевые тесты закрепляют поведение, которое сломает правдоподобная
правка: неизвестная команда — ошибка, а не молча сохранённая заметка; незнакомца
приветствуют один раз, сколько бы он ни стучал; упавшее фото всё равно сообщает,
что кто-то постучался; и залипший `reason=mention` не выдумывает упоминание,
которого нет в тексте комментария.

## Структура

```
src/commands.js   разбор сообщения в намерение — чистая функция, вся логика
src/github.js     Issues API: создать, список, закрыть, повысить, комментарий
src/notify.js     уведомления GitHub: опрос, фильтр, формат, пометка прочитанным
src/html.js       экранирование, общее для обоих путей сообщений
src/index.js      вебхук и cron: проверки, разбор, опрос, ответ
local.js          опрашивающий раннер для тестов
docs/adr/         почему принято каждое несущее решение
```

## Про токен

Токен Telegram лежит в секретах Cloudflare, не в репозитории. GitHub сканирует
публичные репозитории на секреты, сообщает об утёкших токенах Telegram, и те их
отзывают — поэтому закоммиченный токен даёт молча мёртвого бота. Это довод про
надёжность не меньше, чем про безопасность.
