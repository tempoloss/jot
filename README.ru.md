# jot

Telegram-бот, который сохраняет заметки и задачи как GitHub Issues. Без
зависимостей, работает на Cloudflare Workers.

[English version](README.md)

```
купить зарядку         заметка
фото + подпись         заметка с картинкой, /pic 5 вернёт её
/task 5                повысить заметку 5 до задачи
/t текст               сразу задача
/list                  открытые задачи, с возрастом
/notes                 последние заметки
/done 3                закрыть
/c 3 текст             комментарий
```

## Лови без разбора, сортируй потом

Любое обычное сообщение — **заметка**. В момент отправки решать нечего: ни
«задача или заметка», ни категория. Захват безусловный, потому что решение на
захвате — это трение, а трение на захвате убивает личный таскменеджер.

Сортировка отдельно: `/task N` повышает заметку, когда ты уже решил, что это
дело. Заметка — запись, её не закрывают; задачу можно.
См. [ADR 0001](docs/adr/0001-plain-text-is-a-note.md).

## Почему так

| решение | почему | детали |
|---|---|---|
| По умолчанию заметка, не задача | ноль решений на захвате | [ADR 0001](docs/adr/0001-plain-text-is-a-note.md) |
| GitHub Issues как хранилище | уже база задач с API и мобильным приложением | [ADR 0002](docs/adr/0002-github-issues-as-the-store.md) |
| Cloudflare Workers, не рабочий комп | всегда онлайн, не перезагружается, бесплатно | [ADR 0003](docs/adr/0003-cloudflare-workers-not-a-desktop.md) |
| Фото через Telegram `file_id` | без лишних прав, без утечки токена | [ADR 0004](docs/adr/0004-photos-by-file-id.md) |

## Установка

**1. Два приватных репозитория.** Один — этот код, другой, отдельный, —
хранилище задач. Укажешь публичный — все личные заметки станут публичными.

**2. Fine-grained PAT** с **Issues: Read and write**, только на репозиторий
хранилища. Repository access и Permissions — две разные секции, а кнопку Update
token внизу легко пропустить.

**3. Chat id в Telegram.** Сначала напиши боту — `getUpdates` пустой, пока не
напишешь — потом возьми `result[0].message.chat.id` из
`https://api.telegram.org/bot<TOKEN>/getUpdates`.

**4. Деплой:**

```bash
npm i -g wrangler
wrangler login
wrangler secret put TELEGRAM_TOKEN
wrangler secret put GH_PAT
wrangler secret put WEBHOOK_SECRET     # любая случайная строка
wrangler secret put OWNER_CHAT_ID
wrangler secret put TASK_REPO          # owner/tasks
wrangler deploy
```

**5. Зарегистрируй вебхук** с тем же секретом:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://jot.<субдомен>.workers.dev" \
  -d "secret_token=<WEBHOOK_SECRET>"
```

`secret_token` обязателен. Без него ботом управляет любой, кто узнал URL, а URL
воркеров угадываются.

## Локальный запуск

Скопируй `.dev.vars.example` в `.dev.vars`, заполни, затем:

```bash
npm run check    # проверить конфиг, ничего не запуская
npm run local    # опрос, без деплоя
```

`local.js` — только для тестов. Он умирает при перезагрузке и умирает молча —
ровно то, от чего спасает Worker. Он импортирует тот же `dispatch`, что и
Worker, поэтому они не разъедутся.

## Тесты

```bash
npm test
```

Парсер разделён на `fetch` (с сетью) и `parse` (чистая функция), поэтому каждый
путь разбора покрыт без сети. Ключевой тест: неизвестная команда — это ошибка, а
не молча сохранённая заметка.

## Структура

```
src/commands.js   разбор сообщения в намерение — чистая функция, вся логика
src/github.js     Issues API: создать, список, закрыть, повысить, комментарий
src/index.js      вебхук: проверка секрета, проверка владельца, ответ
local.js          опрашивающий раннер для тестов
docs/adr/         почему принято каждое несущее решение
```

## Про токен

Токен Telegram лежит в секретах Cloudflare, не в репозитории. GitHub сканирует
публичные репозитории на секреты, сообщает об утёкших токенах Telegram, и те их
отзывают — поэтому закоммиченный токен даёт молча мёртвого бота. Это довод про
надёжность не меньше, чем про безопасность.
